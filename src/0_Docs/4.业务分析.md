# Backend服务有哪些主要的业务流程?


根据代码库分析，EasySwapBackend的主要业务流程如下：

## 1. 用户认证流程
- 实现代码：`src/api/v1/user.go`中的`UserLoginHandler`、`GetLoginMessageHandler`、`GetSigStatusHandler`
- 功能：处理用户登录、获取登录消息、验证签名状态

## 2. NFT集合管理流程
- 实现代码：`src/api/v1/collection.go`中的`CollectionItemsHandler`、`CollectionDetailHandler`等
- 功能：获取集合详情、集合内物品列表、出价信息等

## 3. NFT物品管理流程
- 实现代码：`src/service/v1/item.go`中的`GetItemBidsInfo`、`src/api/v1/collection.go`中的`ItemDetailHandler`
- 功能：获取单个NFT详情、出价信息、特征信息等

## 4. 订单管理流程
- 实现代码：`src/api/v1/order.go`中的`OrderInfosHandler`
- 功能：处理订单信息查询

## 5. 活动记录流程
- 实现代码：`src/api/v1/activity.go`中的`ActivityMultiChainHandler`
- 功能：获取多链活动记录

## 6. 投资组合管理流程
- 实现代码：`src/api/v1/portfolio.go`中的多个Handler
- 功能：管理用户的多链收藏品、物品、挂单和出价

## 7. 排行榜流程
- 实现代码：`src/api/v1/ranking.go`中的`TopRankingHandler`
- 功能：获取NFT集合排行榜

## 8. 缓存管理流程
- 实现代码：`src/api/middleware/cacheapi.go`
- 功能：实现API响应缓存机制

这些业务流程通过Gin框架的路由系统(`src/api/router/`)进行组织，并通过中间件(`src/api/middleware/`)提供通用功能支持。服务层(`src/service/v1/`)负责具体的业务逻辑实现，数据访问层(`src/dao/`)处理数据库操作。



# `src/api/router/`   `src/api/v1/`  `src/service/v1/` 下面的类是什么关系?


根据代码库分析，这三个目录下的类存在清晰的分层架构关系：

## 1. **src/api/router/** - 路由层
- 负责URL路由定义和HTTP请求分发
- 通过`router.go`和`v1.go`组织API路由结构
- 将请求路由到对应的处理函数

## 2. **src/api/v1/** - 控制器层
- 包含各个业务模块的HTTP处理函数(Handler)
- 例如`user.go`、`collection.go`等文件中的Handler函数
- 负责处理HTTP请求，调用service层处理业务逻辑

## 3. **src/service/v1/** - 服务层
- 实现具体的业务逻辑
- 包含如`user.go`、`collection.go`等服务实现
- 被控制器层调用，处理数据转换和业务规则

## 4. **数据流向**:
```
HTTP请求 → router层 → api/v1层(Handler) → service/v1层 → 数据库
```

## 5. **依赖关系**:
- router层依赖api/v1层的Handler
- api/v1层依赖service/v1层的服务实现
- service/v1层负责具体的业务逻辑处理

这种分层架构使得代码结构清晰，职责分明，便于维护和扩展。每一层都有其特定的职责，通过依赖注入的方式组织在一起。
